Project Overview

Spring, 2025 - Fall, 2026

A collaboration-wide package that centralizes the variable mappings needed to interpret SuperCDMS data across many years of detector operation, processing versions, and analysis software.

The package provides a common source of truth for the names, identifiers, and relationships used to interpret processed data. It is designed to support the development of new SuperCDMS code without requiring each project to reconstruct the same historical mappings independently.

The Problem It Solves

SuperCDMS data have been produced over many years using different detector configurations, processing versions, and software environments. The meaning of a variable can depend on that historical context, so analysis and processing libraries need a reliable way to translate between stored data and the physical or detector quantities they represent.

Before this package, individual libraries could need to reproduce and update those mappings independently. That created duplicated effort and made it easier for projects to drift apart or interpret the same data differently.

Shared Package Design

Global Mappings combines a database with a CSV representation of the mapping information. The database provides structured access to the complete collection of definitions, while the CSV file makes the contents easy to inspect, review, version, and use in development workflows.

Keeping the mapping information separate from individual analysis applications means that updates can be made once and consumed by many downstream projects. New code can query the shared package instead of embedding another local copy of historical detector knowledge.

C++ and Python Interface

The core library is implemented in C++ and exposed to Python through Boost.Python. This combination allows the package to provide a compiled, shared implementation for performance-sensitive or existing C++ code while remaining accessible to Python analysis and development projects.

The interface gives developers a consistent way to retrieve the values needed to interpret data, regardless of whether the surrounding project is written primarily in C++ or Python. It also places the mapping logic behind a reusable API instead of requiring every project to parse files or maintain its own conversion rules.

Scale and Distribution

The system centralizes hundreds of detector and configuration parameters that had previously been hard-coded independently across software projects. It is distributed through collaboration containerized offline-software releases, allowing new code to use the same mappings in controlled and reproducible environments.

Collaboration-Wide Impact

Because the package is used across the collaboration, it serves as infrastructure rather than a single analysis result. Processing tools, reconstruction-related projects, validation code, and new analysis applications can all rely on the same definitions.

This shared approach improves consistency, reduces duplicated maintenance, and makes it easier to develop new projects against data from different detector eras. When the historical mapping is updated, the change can be reviewed and propagated through one maintained package instead of being rediscovered in multiple independent libraries.

Project Details

I developed the Global Mappings package to make SuperCDMS data interpretation more maintainable across the collaboration. The project combines database design, structured data modeling, C++ library development, Boost.Python bindings, CSV-based interchange, and scientific software integration.
