Project Overview

Fall, 2026 - Present

AI Resume Tailor creates a job-specific resume, cover letter, and alignment notes from a resume file and a public job-posting URL. It uses the OpenAI Responses API to turn the source materials into application-ready drafts while keeping human review in the workflow.

View the project on GitHub

How the Process Works

The program begins by reading the resume file and converting its contents into text that can be analyzed consistently. Supporting several common formats makes the tool useful with existing application materials instead of requiring the user to rewrite a resume for the program.

It then requests the public job page and reads the page's Open Graph title and description. These fields provide a predictable, lightweight way to identify the role and capture its summary without attempting to execute arbitrary page JavaScript or scrape an entire website.

The resume text and job-posting information are sent to the OpenAI Responses API with instructions to create three separate documents. The results are saved using the job ID, which keeps applications organized and makes it possible to compare the generated materials for different roles.

Workflow

  1. Extract text from a .txt, .md, .pdf, or .docx resume.
  2. Fetch a public job posting and read its Open Graph title and description.
  3. Use the OpenAI Responses API to generate tailored application documents.
  4. Write the results to a job-specific output directory.

Generated Documents

  • tailored_resume.md: an ATS-friendly resume tailored to the posting.
  • cover_letter.md: a tailored cover letter.
  • alignment_notes.md: addressed requirements, genuine gaps, and the source job URL.
  • PDF versions of each document can be generated through Microsoft Word on Windows.

Implementation

The application is built as an end-to-end Python workflow. It accepts a job-posting URL, retrieves and parses the page with Requests and Beautiful Soup, compares the requirements with resume content through the OpenAI API, generates Markdown documents, and converts those documents into finished PDFs through Microsoft Word automation on Windows.

The project combines API integration, document extraction, structured model output, filesystem organization, command-line interfaces, and reproducible document generation in one practical software tool.

Design Principles

The tool treats the resume as the source of truth. The model may reorganize and emphasize relevant experience, but the instructions explicitly prohibit inventing employers, dates, degrees, metrics, certifications, or duties. The structured JSON response format gives the program three named outputs instead of relying on fragile text splitting, which makes the files easier to save and inspect.

Several small safeguards support that goal. Resume and job-posting text are cleaned and capped before being sent to the model, URLs are validated as public HTTP or HTTPS pages, and the job-posting content is marked as untrusted reference material. The application also keeps credentials outside generated documents by accepting an environment variable or a local ignored key file.

Why Human Review Matters

The tool is designed to organize and tailor information already present in the source resume, not to invent qualifications. Alignment notes make both matched requirements and genuine gaps visible, while the final review step helps catch inaccurate wording, unsupported claims, or context that the source documents did not provide.

Usage

The command-line tool accepts a resume path and public job URL. It also supports custom output directories, OpenAI models, and applicant names:

python applier.py path\to\resume.pdf https://example.com/jobs/JR2026123

Requirements and Limitations

Python 3.10 or newer, an OpenAI API key, and a public HTML job-posting URL are required. The job URL must contain an ID in the form JR<number>. JavaScript-only pages or sites that block automated requests may not work, and job text is currently limited to Open Graph metadata.

Generated documents must be reviewed for accuracy before they are used in an application. API keys should be supplied through an environment variable or a local ignored key file and never committed to the repository.

Future Directions

Future improvements could add more robust extraction for job pages whose useful content is not present in Open Graph metadata, support additional document formats, and provide a dry-run mode that shows the extracted inputs before an API call. Another useful direction would be a comparison view that highlights which resume evidence supports each requested qualification.
