Project Overview

Spring, 2025 - Fall, 2026

cdmsproctools is an automated validation and quick-look monitoring layer for the SuperCDMS processing pipeline. After data have been reconstructed, the results are stored, labeled with their processing context, and plotted so researchers can make a fast first assessment of the data.

This work is distinct from a separate, post-processing analysis script. The validation tools operate as part of the SuperCDMS pipeline itself, helping expose processing problems close to the stage where they are introduced.

Where It Fits in the Pipeline

SuperCDMS detector data passes through a sequence of processing steps that turn raw readout into calibrated and reconstructed quantities. Each step depends on the output of the previous one, so a problem in an early stage can appear later as an unexpected spectrum, a malformed quantity, a missing channel, or a run that cannot be trusted.

The offline data validation layer sits alongside that processing sequence. It consumes the products generated by the pipeline, applies checks and comparisons, and organizes the resulting diagnostics so processing developers and analysts can decide whether a run or processing version is behaving as expected.

What Gets Validated

Validation is about more than checking whether a job finished without an error. It examines whether the resulting data are sensible and consistent. Depending on the processing stage, that can include checking available runs and channels, distributions of reconstructed quantities, event counts, timing and noise behavior, calibration outputs, and changes between processing configurations.

The output is intended to make unusual behavior visible: missing or incomplete data, unexpected shifts in distributions, unstable channels, processing regressions, and other features that merit investigation before the data are used downstream.

Stored and Plotted Results

The validation products are organized so that a result can be traced back to the relevant facility, processing version, detector, channel, run, or series. This labeling is important because a plot without its processing context is difficult to interpret or reproduce.

The plots are designed for a quick first look rather than replacing a detailed analysis. They provide an efficient way to see whether reconstructed quantities have reasonable distributions, whether channels look stable, and whether a processing change produced an obvious difference. When something looks unusual, the plot points analysts toward the runs, channels, or processing stages that need deeper investigation.

Scale and Automation

The package contains several thousand lines of Python and automatically generates and organizes 864 diagnostic plots for a full run. What previously required a several-hour manual analysis can now run essentially unattended, producing a consistent first-look record for the processed data.

The project was adopted across the SuperCDMS collaboration. I own its ongoing software lifecycle, including architecture, code review, unit testing, integration, versioned releases, backwards compatibility, documentation, and defect resolution.

Validation Workflow

  1. Select a SuperCDMS processing product, run range, detector configuration, or processing version to examine.
  2. Read the pipeline outputs using the same data conventions expected by the surrounding processing tools.
  3. Apply validation checks and produce diagnostic summaries, plots, or tables for the selected data.
  4. Compare the results with expected behavior, reference processing, or neighboring runs.
  5. Use the findings to identify problems in data quality, configuration, calibration, or the processing code itself.

Keeping this workflow offline is useful because it allows large collections of processed data to be inspected repeatedly without disturbing production jobs. It also makes validation reproducible: the same processing outputs can be checked again after a code change or a new calibration configuration.

Project Details

I developed and maintained validation tooling that connects directly to the SuperCDMS processing environment, with an emphasis on making reconstructed detector data easy to store, label, plot, and inspect at scale. The project combines scientific data handling, production-workflow integration, diagnostic analysis, and practical software maintenance.

The restricted collaboration validation pages provide examples of the kind of run- and processing-level output this work supports. Access to those pages requires SuperCDMS credentials; the public description here focuses on the role of the validation layer rather than reproducing restricted data or interfaces.
